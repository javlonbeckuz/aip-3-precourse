# UX/UI audit: AI Praktikum 3.0 student portal, 2026-10-30

- **Walked:** the real app (`public/aip/`) on `127.0.0.1:3203` (clock 26 Dec 2026, course running) and a second instance on `3204` (clock 10 Nov 2026, before the course). Demo student `XM`. Headless Chrome over CDP at 1440×900 and 390×844 (mobile emulation), in UZ, RU and EN.
- **Build note:** three commits landed while the audit ran (`d3854c2` Kit tab, `866698d` Kit material, `e46077b` setup without the Warp card). Every screenshot was retaken after `e46077b`, so the shots and findings match that build.
- **Measured, not eyeballed:** an in-page probe listed every visible text under 15px, every target under 44px (counting `::after` hit areas), clipped text, horizontal overflow and contrast against the nearest solid background. Result: no overflow and no clipping at 390 or 1440 in any language, no console errors, no solid-background contrast failures, and a visible 2px white focus ring on every control in tab order. What is left is size, wording, meaning and flow.
- **Checked against:** `taste-profile.md`, `ux-spec.md`, `ux-audit.md` (10-16) and `ux-pass-2.md` (10-17). Older findings are re-checked at the end of this file.
- **Out of scope:** the user's recent decisions (W1 full-width lesson page with a one-line header, M3 roadmap with chips, Poʻlat lesson folders, glass accordion, style C coupon, per-lesson home colours). Only their execution is questioned here.
- **Screenshots:** `.design/audit-2026-10-30/`. Names are `NN-screen-desktop.png` / `NN-screen-phone.png`.
- **Severity:** P1 = blocks or misleads a student. P2 = slows or confuses. P3 = polish. **Effort:** S < 1 h, M = half a day, L = more.

## S0 · Across all screens

### S0-1 · P2 · Small text a student has to read, mostly on phones
- **Where:** all screens, mostly at 390.
- **What is wrong:** the user asked for larger text, but these are still under 15px:

| Element | Size | Where |
|---|---|---|
| Card labels and state notes (`.f-label`, `.f-note`): "01-DARS · 21-NOYABR", "OCHIQ · 0/2 BAJARILDI", "SANA KEYINROQ" | 13px uppercase | home, 390 |
| Lesson meta under the back link (`.dl-m`): "21-NOYABR · 0/2 BAJARILDI" | 13px uppercase | lesson, setup, kursgacha |
| Back link "← DASTUR" (`.eyebrow`) | 13px | every inner page |
| Folder tabs "AMALIYOT / KIT / VAZIFA" (`.gt-tab`) | 13px uppercase | lesson, both widths |
| Roadmap stop numbers (`.m3-dot`) | 12px mono | lesson |
| "Qayerga: Claude" (`.pchips .to`) | 14px at 85% white | open prompt chip |
| File sizes in file chips (`.fz`) | 12px | Kit tab |
| Coupon label "PROMOKOD, 100% CHEGIRMA" (`.ia-k`) and row subtitles (`.ia-s`) | 12px / 14px | kursgacha |
| Section heads "MASHQ VA VIDEO DARS", "QOʻLLANMA" (`.ef-h`) | 13px | kursgacha, setup |
| Login help and error line (`#gid-h`) | 13px on the photo | login |
| "START" in the lesson 01 badge | 11.5px | home |

- **Why it matters:** these lines carry the state ("open, 0 of 2 done"), the date and the paste target. A business owner reading on a phone at arm's length skips them.
- **Fix:** set a 15px floor for everything a student reads, keeping the uppercase where the look wants it:

```css
.f-label,.f-note,.dl-m,.eyebrow,.ef-h,.ia-k{font-size:15px}
.gt-tab{font-size:15px}
.pchips .to{font-size:16px}
.ia-s,.fz{font-size:15px}
#gid-h{font-size:15px}
```

  The card note may then wrap at 390. That is fine, because S0-3 shortens it.
- **Effort:** S. **Shots:** `03-home-during-phone.png`, `06-lesson1-top-phone.png`, `05-kursgacha-phone.png`.

### S0-2 · P2 · The moving background lines run behind running text
- **Where:** the ledes on setup, Birinchi darsgacha and the lesson header; the ring area on home. Both widths, worst at 1440.
- **What is wrong:** the fixed `.bgp` line field (opacity .22) crosses the grey lede text. In `05-kursgacha-desktop.png`, "boʻladigan materiallar va foydali oʻquv platformalariga" has bright strokes through it.
- **Why it matters:** the grey lede (`--text-2`) is already the faintest body text, and the strokes cut through letters. This breaks `ux-spec` §4.1: "Decorative texture never sits behind running text."
- **Fix:** keep the lines but give text a black halo, so no layout change is needed:

```css
.lede,.lsub,.lh1,.dl-h,.prog .pt{position:relative;z-index:1;text-shadow:0 0 8px #000,0 0 16px #000}
```

  Alternative: drop `.bgp` opacity to `.12` on `body[data-view="ex"]` and `[data-view="dars"]`.
- **Effort:** S. **Shots:** `05-kursgacha-desktop.png`, `04-setup-desktop.png`, `06-lesson1-top-desktop.png`.

### S0-3 · P2 · Counters without a unit, and "·" chains
- **Where:** home cards, lesson meta, the home pill, the menu.
- **What is wrong:**
  - "0/2 bajarildi" never says what the 2 are. They are the Amaliyot and Vazifa end ticks. ux-audit H4 asked for a unit every time; that fix has regressed.
  - Three-part "·" chains:
    - "Qolib ketgan ish · 01-dars · Amaliyot"
    - "Hozir davom etmoqda · 0/2 bajarildi"
    - "Kurs · 6 dars"
    - "6 dars · 21-noyabr – 26-dekabr"
    - "prep-uz.pdf · PDF yuklab olish"
- **Why it matters:** "0/2" on a lesson with 5 roadmap stops and 10 prompts reads as wrong, or as two of something unknown. The user has banned "·" chains.
- **Fix (copy, UZ):**
  - Card note: "Ochiq · 0/2 bajarildi" → **"Amaliyot va vazifa: 0/2"**. When done: **"Amaliyot va vazifa bajarildi"**.
  - Lesson meta: "21-noyabr · 0/2 bajarildi" → **"21-noyabr. Amaliyot va vazifa: 0/2"**.
  - Pill: **"Qolib ketgan ish: 1-dars amaliyoti"** (see also S3-1).
  - Live note: **"Hozir davom etmoqda"** only. The count is already on the lesson page.
  - RU and EN follow the same pattern.
- **Effort:** S. **Shots:** `03-home-during-desktop.png`, `06-lesson1-top-phone.png`.

### S0-4 · P2 · Colour still looks like state, but no longer means state
- **Where:** home, both widths.
- **What is wrong:**
  - `taste-profile.md` still says "Blue = now, dark = locked, grey = material". With per-lesson colours, the home page now shows:
    - 03-dars, which is open, as a near-black card. It reads as locked.
    - Kirish, which is locked, as a light grey card. It reads as open material.
    - 02-dars, which is just open, in blue. It reads as "now".
    - Before the course, the locked "Barcha darslar" folder in blue.
  - The only real state signal is the 13px note at the bottom of each card.
- **Why it matters:** students scan colour before they read text. A student looking for the locked lesson finds the dark 03 card. This is the same trap as the "01 02 03" avatar cluster: it looks like data but isn't.
- **Fix (the colours stay):**
  - Make the state legible without colour. Locked cards get the 14px lock grown to 20px next to the note, and the note at 15px (S0-1).
  - Update the colour-meaning line in `taste-profile.md` so the next designer doesn't rely on it: colours now identify lessons, and state is carried by the note and the lock.
- **Effort:** S. **Shot:** `03-home-during-desktop.png`.

### S0-5 · P2 · Setup uses the Birinchi darsgacha yellow
- **Where:** `/aip/dars/0` cards, both widths.
- **What is wrong:**
  - The four (now three) setup cards are `c-yellow`, while the setup card on home is terracotta (`c-claude`).
  - Yellow is the "Birinchi darsgacha" colour by user decision, and that yellow pill sits in the header of the same page.
  - The student taps an orange card and lands on a yellow page that matches the other section's button.
- **Why it matters:** the two prep areas are already easy to mix up ("Tayyorgarlik" vs "Birinchi darsgacha"). Colour is now pushing them together.
- **Fix:** paint the setup cards in the setup lesson's own colour (`c-claude`, black text, which passes) or in Poʻlat, to follow the "inside a lesson = Poʻlat" rule. One class in `prepPage()`: `folder flatc c-yellow pc` → `folder flatc c-claude pc`.
- **Effort:** S. **Shots:** `04-setup-desktop.png`, `03-home-during-desktop.png`.

## S3 · Home during the course (3203, 26 Dec)

**What works:**
- The live lesson is the first thing under the ring, and every lesson is one tap away.
- Keyboard order runs home, Birinchi darsgacha, name, hero, pill, cards, with a visible 2px white ring on each.
- No overflow at either width.

### S3-1 · P1 · Unfinished setup is no longer offered as the next step (regression from `e46077b`)
- **Where:** `nextStep()` in `app.js`; the home pill.
- **What is wrong:**

```js
if (courseStarted() && PREP.items.length > 3) { const i = [1, 2, 3].find(j => !S.has('prep:' + j)); ... }
```

  Setup now has 3 items, so the condition is false. A student with **0/3 setup done** gets "Qolib ketgan ish · 01-dars · Amaliyot". Before this commit the same student got "Tayyorgarlik · Google akkaunt" (seen live during the audit).
- **Why it matters:**
  - A student without a Google account or a Claude plan cannot do any lesson's practice.
  - The one nudge that told them so has silently disappeared, and the pill sends them into lesson 1's practice instead.
- **Fix:** follow the content instead of fixed indexes:

```js
if (courseStarted()) { const i = PREP.items.findIndex((_, j) => j > 0 && !S.has('prep:' + j)); if (i > 0) return {href: '#/dars/0', label: T('next.prep', {title: HT(T(`prep.${i}.title`))})}; }
```

  Add one test in `server/app.test.js` (or the front-end smoke test) with 3 prep items and none ticked.
- **Effort:** S. **Shot:** `09-menu-desktop.png` (the pill behind the menu shows "01-dars · Amaliyot" with setup at 0/3).

### S3-2 · P2 · The hero subtitle is a single bare word
- **Where:** the live hero card, "Amaliyot".
- **What is wrong:** the subtitle names a tab but not an action. It also repeats a word the student sees again as the first tab.
- **Fix:** **"Bugungi amaliyot: 5 bosqich"**, built from the roadmap group count. Use **"Amaliyotni davom ettirish"** once a prompt is copied.
- **Effort:** S. **Shot:** `03-home-during-phone.png`.

### S3-3 · P3 · The START badge and the finish flags look like status badges
- **Where:** the 01 card (two chequered flags with "START"), the 06 card (one chequered flag next to the live note).
- **What is wrong:**
  - A chequered flag means "finish", so "START" between two chequered flags contradicts itself.
  - On 06, the flag sits in the same row as "HOZIR DAVOM ETMOQDA · 0/2 BAJARILDI" and squeezes it to two lines at 1440.
  - Both read as a state ("started", "finished") that the student doesn't have.
- **Fix (execution only, the badge stays):**
  - Use a plain solid flag for START and keep the chequered one for 06.
  - Move both above the note row (`.f-flag{bottom:auto;top:...}`) so they never share a line with state text.
  - Raise "START" to 13px.
- **Effort:** S. **Shot:** `03-home-during-desktop.png`.

### S3-4 · P3 · "Ochiq" on every open card is noise
- **What is wrong:** all 7 open cards say "OCHIQ ·". The state that matters is the exception: locked, done, or live.
- **Fix:** drop "Ochiq ·" from `note.open`. With S0-3 the note becomes "Amaliyot va vazifa: 0/2".

### S3-5 · P3 · Only the Kirish card has a topic line

### S3-6 · P3 · The cream lesson 6 hero sits next to the yellow Birinchi darsgacha pill

- **Fix:** none needed until the course reaches lesson 6. If it bothers in review, darken lesson 6's cream one step.

## S6 · Lesson page (`/aip/dars/1`, `/aip/dars/7`)

**What works:**
- The one-line header ("← DASTUR · 21-NOYABR …") and the full-width Poʻlat folder match W1.
- The roadmap is easy to follow: a numbered stop, a lead line, numbered steps, and "Tayyor, agar …", a concrete definition of done for each stop. Keep it.
- Opening a chip shows "Qayerga" and the full prompt at 16px/1.6 with placeholders in bold.
- Copying marks the chip ✓ and shows an undo toast.
- The keyboard reaches tab, chip and copy in reading order.

### S6-1 · P2 · Copy is an unlabelled 36px icon inside a 46px chip
- **Where:** `.pchips .cp` (the `.cpl` label is `display:none`), both widths.
- **What is wrong:**
  - This is the most important control in the product, and it is an icon with no word. That breaks `ux-spec` §3.4 ("never an icon alone"); ux-audit H2 has regressed.
  - Its 36×36 target sits inside the chip's own tap area. A near-miss opens the chip instead of copying.
- **Why it matters:** non-technical students will not read the two-squares icon as "copy". They open the chip and long-press the text instead, and then nothing is marked done.
- **Fix:**
  - Show the label on the open chip, so a closed chip stays compact:

```css
.pchips .cp{width:44px;height:44px}
.pchip>summary{min-height:52px}
.pchip[open] .cp{width:auto;padding:0 14px 0 10px;border-radius:999px;gap:6px}
.pchip[open] .cpl{display:inline}
```

  - Use the S0-1 floor (15px) for `.cpl`.
- **Effort:** S. **Shots:** `06-lesson1-chip-open-phone.png`, `06-lesson1-desktop.png`.

### S6-2 · P2 · Nothing says a chip opens
- **What is wrong:** a closed chip is a pill with a title and a copy circle: no chevron, no "matn", no "+". The open chip's pill looks exactly like a closed one.
- **Why it matters:** students read the chips as tags, copy blind without seeing the "[qavslar]" to fill in, and paste a prompt full of placeholders.
- **Fix:**
  - A ⌄ after the title that rotates on open: `.pchip>summary .tt::after{content:"";...}`. The rule `.pchips .tt::after{content:none}` currently kills it.
  - `.pchip[open]>summary{background:rgb(255 255 255/.16)}`
- **Effort:** S. **Shot:** `06-lesson1-chip-open-phone.png`.

### S6-3 · P2 · The paste target is the faintest line in the open chip
- **Where:** `.pchips .to` ("Qayerga: Claude"), 14px at 85% white.
- **What is wrong:** this is ux-audit H2's "target line" problem again. "NotebookLM → Studio → Quiz" is the instruction students get wrong.
- **Fix:** `.pchips .to{font-size:16px;color:var(--gt-ink)}` and `.pchips .to b{font-weight:700}`.
- **Effort:** S. **Shot:** `06-lesson1-chip-open-phone.png`.

### S6-4 · P2 · The toast names a prompt ID the student never sees
- **Where:** the copy toast "01P3 nusxalandi. Claudeʼda [qavslar]ni …".
- **What is wrong:** chips hide their `.no` IDs, so "01P3" appears nowhere on screen.
- **Why it matters:** the student can't tell which prompt was copied, or which one "Bekor qilish" will undo.
- **Fix:** use the chip title: **"«Bitta oʻzgartirish» nusxalandi. Claudeʼda [qavslar]ni oʻz maʼlumotingiz bilan almashtiring."** It is already in `li.dataset.t`.
- **Effort:** S. **Shot:** `06-lesson1-copy-ok-desktop.png`.

### S6-5 · P2 · Progress ignores the work, and the end of the pane is a dead end
- **Where:** the "Amaliyot bajarildi" tick, bottom right of the pane.
- **What is wrong:**
  - Copying all 10 prompts leaves the lesson at "0/2". Only the end tick counts, and it sits at the bottom right after 2,900px (desktop) or 4,700px (phone).
